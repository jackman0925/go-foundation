# 文件大小展示规范

本规范源自文件大小展示需求，已由 filex 实现。

## 单位与精度

- 存储、传输、限制和校验以整数 bytes 为唯一事实来源，展示文本不参与计算。
- 默认使用十进制，1000 进位：B、kB、MB、GB、TB、PB。
- 工程诊断显式使用二进制，1024 进位：B、KiB、MiB、GiB、TiB、PiB。
- B 显示整数；kB/MB、KiB/MiB 最多 1 位小数；更大单位最多 2 位小数。
- 按绝对值四舍五入，恰好一半时向远离零方向舍入；去除无意义末尾零。
- 舍入达到下一单位时晋升，并从原始字节数重新计算。最大单位固定为 PB/PiB。
- 支持完整 int64 范围；零显示为 `0 B`，负数保留符号。负数处理不代表文件允许负大小。
- 数字和单位之间一个 ASCII 空格，无千位分隔符，小数点固定为点号。

`18,877,622,182` 字节显示为 `18.88 GB`，诊断二进制值为 `17.58 GiB`。
不能将二进制换算结果标为 GB。

## 接口与边界

```go
filex.FormatDecimalSize(18877622182) // "18.88 GB"
filex.FormatBinarySize(18877622182)  // "17.58 GiB"
```

使用整数运算避免大整数浮点误差。函数不读取文件、不解析配置，不改变上传限制、
配额或计费语义；ParseSize 等配置解析不属于本需求。

## 前后端一致性

语言无关样例见 [size_display.json](testdata/size_display.json)。
bytes 字段采用十进制字符串，避免 JSON 消费端丢失精度。JavaScript 的完整范围
实现应直接使用 BigInt 解析该字符串，不能先转 Number。

服务端文件元数据应同时提供原始大小及展示文本；超过 JavaScript 安全整数范围的
原始值按接口契约以字符串传输。浏览器上传前的 File.size 由前端轻量实现处理，
使用同一样例验证。此 Go 库不提供浏览器运行时代码。

产品接入时应统一文件列表、搜索、上传队列、冲突提示、版本、回收站、分享、
下载记录、管理后台容量、API 展示字段及日志。调用方负责删除本地重复逻辑，
并增加前后端展示一致性测试。
